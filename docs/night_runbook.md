# Election night runbook (2026-11-03)

Monitor (Mac, read-only, never restarts anything): `uv run python analysis/night_monitor.py --loop` (waits for 17:30 UTC, then every 2 min; add `--once` for a single run).
Output: `~/brunder-night/monitor.log` (one line per run), `~/brunder-night/status.json`, `ALERT: …` / `WARN: …` on stdout. Known, accepted problems: one substring per line in `~/brunder-night/ack.txt` turns the matching ALERT into a WARN.
VM shorthand: `V='ssh oracle-slotbank'`; every VM command below is read-only.

## Checklist

| When (UTC) | Do |
|---|---|
| T-60 min (≈ 17:00, before 18:00 recorders start) | `uv run python analysis/night_monitor.py --once` → no ALERT, all units `inactive/dead (waiting)`. `$V 'systemctl list-timers "brunder-*" --no-pager'` → snap/kalshi/civic/pm-ws at 18:00, election-night at 22:30. `$V 'df -h /; uptime'`. Start `--loop` in a terminal/tmux. Pull `main` on Pages check: monitor WARNs if Pages `election.js` differs from the checkout. |
| 18:00 | Recorders start. Within 3 min: `$V 'systemctl is-active brunder-snap-us brunder-kalshi-us brunder-pm-ws-us brunder-civic-us'` → 4× active. Feeds answering 404 are normal until each state publishes (WARN only). |
| 22:30 | Live model, site and tunnel start. Read the tunnel URL once: `$V 'sudo -n journalctl -u brunder-tunnel -o cat | grep -o "https://[a-z0-9-]*\.trycloudflare\.com" | tail -1'`. Publish `…/election.html?id=us2026&live=<URL>`: write the URL into `site/data/live_link.json` (`url`) and push that one file — every public page (landing, election, guide, early vote, turnout) opened without `&live=` then shows a "Live now" pill linking to itself with `&live=` (`site/live-link.js`). Within 5 min the monitor's browser check shows "Live · updated". |
| 23:00+ polls close | Watch `ALERT: feed …` (403/429/5xx/timeouts = blocked or down) and `counted` progress in `status.json` (`info.races.us_summary`). |
| every hour | `tail -n 30 ~/brunder-night/monitor.log`; `$V 'df -h /; uptime; free -m'`; open the public link once by hand. |

## Failures: diagnose (read-only) → safe action (integrator runs it; nothing is automated)

| Failure (monitor line) | Diagnose | Safe action |
|---|---|---|
| Feed 403 / stale (`ALERT: feed <key> [403, n fails…]`) | `$V 'sudo -n cat /srv/brunder/repo/data/raw/snap/us_midterms_2026/.poll/snap.json' \| python3 -m json.tool \| grep -B1 -A4 <key>`; `curl -sI "<feed url>"` from the Mac (is it the VM IP that is blocked?) | A 403/202 bot challenge: do not circumvent; leave the feed, note it in `ack.txt`. A timeout/5xx: wait (recorder backs off by itself). Recorder itself hung: `sudo systemctl restart brunder-snap-us` (the recorder keeps its dedupe in memory: first poll re-saves each feed once, harmless). |
| Recorder poll marker old / unit down (`brunder-snap-us`, `-kalshi-us`, `-civic-us`, `-pm-ws-us`) | `$V 'sudo -n systemctl status brunder-snap-us --no-pager -l \| head -30; sudo -n journalctl -u brunder-snap-us -n 60 -o cat --no-pager'` | `sudo systemctl restart brunder-<unit>` on the VM (`ssh oracle-slotbank`). The live model re-reads the archive, nothing is lost. |
| Tunnel down / new URL (`ALERT: tunnel URL changed`, `public … HTTP None/502/530`) | `$V 'systemctl is-active brunder-site brunder-tunnel; sudo -n journalctl -u brunder-tunnel -n 30 -o cat --no-pager'`; `$V 'curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8790/elections.json'` (site OK locally?) | Site 200 locally, tunnel dead: `sudo systemctl restart brunder-tunnel`, then read the new URL (command in the 22:30 row) and re-publish the link: update `site/data/live_link.json` and push it (links already shared with the old URL go dead; the pill on the plain pages points to the new one). The monitor picks the new URL up on its next run. Site itself down: `sudo systemctl restart brunder-site` (the tunnel `Requires=` it and restarts with it → new URL). |
| Model crash / stale (`ALERT: brunder-us-live … not written`, `crash-looping`, `traceback`) | `$V 'sudo -n journalctl -u brunder-us-live -n 100 -o cat --no-pager'`; `$V 'sudo -n stat -c "%y %n" /srv/brunder/repo/site/data/us2026/timeline_tail.json'`; are recorders fresh (`.poll` marker)? A model that waits for a stale recorder is a recorder problem first | Units auto-restart (`Restart=on-failure`, 30 s). If it stays down/failed: `sudo systemctl restart brunder-us-live` (or `-us-house-live`, `-us-national`, `-us-civic-live`). Each race has its own cursor; a crashed process resumes from the archive. |
| VM disk / CPU / memory (`VM disk 85%`, `VM load`, `free memory`, `kernel OOM`) | `$V 'df -h /; du -xsh /srv/brunder/repo/data/raw/snap/* 2>/dev/null \| sort -h \| tail -5; uptime; free -m; ps -eo pcpu,rss,cmd --sort=-pcpu \| head -8'`; `$V 'sudo -n journalctl -k --since -30min \| grep -i oom'` | Disk: free space only from things you wrote yourself (old `/tmp`, journals: `sudo journalctl --vacuum-size=200M`); never delete the snapshot archive. CPU/memory: services are capped (`CPUQuota`, `MemoryMax`); an OOM-killed unit restarts by itself — restart only if it did not. |
| Pages stale / broken (`WARN: GitHub Pages election.js differs`, `GitHub Pages … HTTP 404`) | `curl -sI https://andylol111.github.io/understanding-brazilian-information-underpricing/election.js \| grep -i last-modified`; `gh run list --workflow pages --limit 3` (or the repo's Actions tab); `git log -1 --format=%cd origin/main` | Failed deploy: re-run it from the Actions tab (`gh run rerun <id>`). Do not push new code on the night unless the live page is broken. |
| Browser check (`console error`, `Live · updated N s ago` > 180 s, `Reconnecting…`) | Open the public link by hand; `curl -sI <tunnel>/us2026/timeline_tail.json` (Last-Modified fresh?); `status.json` → `browser.console_errors` | Fresh files + stale page = the tunnel or the page's CORS/URL (a wrong `&live=` after a tunnel restart): re-publish the current URL. Stale files: see "Model crash / stale". |
| ssh fails (`VM unreachable`) | `ssh -v oracle-slotbank true`; Oracle console | Network from the Mac first (`ping`); the VM keeps running by itself — the recorders do not depend on this monitor. |
